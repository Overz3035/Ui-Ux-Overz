UIUX ENGINE — RESOURCE LIST



Purpose



This file contains all external skills, libraries, frameworks, design systems, inspiration websites, motion resources, 3D resources, and GitHub repositories that should be evaluated and integrated into the UIUX ENGINE.



The engine must NOT blindly merge everything.



Each resource must be classified, analyzed, and integrated according to its actual role.

9\. Resource Integration Rules



The UIUX ENGINE must distinguish between:



ACTIVE ENGINES



Resources that provide actual reasoning/workflow/CLI capabilities.



Example:



\- UI UX Pro Max



These should be invoked when appropriate.



SKILLS



Resources containing reusable knowledge or methodology.



Example:



\- Taste

\- Frontend Design

\- Motion Design Skill



LIBRARIES



Technical implementation dependencies.



Example:



\- Framer Motion

\- GSAP

\- Three.js

\- React Three Fiber



COMPONENT RESOURCES



Reusable UI implementation/reference sources.



Example:



\- 21st.dev

\- React Bits

\- Uiverse

\- Lightswind

\- Three UI

\- LiquidGlass.js



INSPIRATION SOURCES



Websites used primarily for visual/reference research.



Example:



\- Scrolltide

\- Motionsites

\- Vividsites

\- Horizonx



KNOWLEDGE TOOLS



Tools whose concepts can influence the internal knowledge architecture.



Example:



\- Obsidian



ENGINEERING RESOURCES



Resources relevant to software engineering and agent workflows.



Example:



\- ECC

10\. Critical Design Rule



The UIUX ENGINE must NEVER produce identical websites from these resources.



Resources are KNOWLEDGE.



They are NOT TEMPLATES.



The engine must extract:



\- principles

\- patterns

\- techniques

\- interaction models

\- motion principles

\- composition principles

\- accessibility rules

\- UX heuristics

\- implementation techniques



But it must generate a NEW Design DNA for every project.



\---



11\. Priority Hierarchy



Use this order:



1\. User requirements

2\. Project requirements

3\. Product/audience requirements

4\. Accessibility

5\. UX usability

6\. Existing project design system

7\. Brand requirements

8\. Technical constraints

9\. UIUX ENGINE core principles

10\. External skills

11\. External libraries

12\. Visual references



Never allow an external resource to override explicit project requirements.

12\. Reference Images \& Videos



All local reference assets must be treated as knowledge.



The engine should:



\- analyze

\- classify

\- tag

\- rename

\- deduplicate

\- cluster

\- index

\- embed

\- preserve source relationships



Original files must NEVER be deleted automatically.



\---



13\. Reference Search



The engine must support semantic reference retrieval.



Example:



User:



"Create a premium industrial dashboard with dense data and cinematic motion."



The engine should retrieve only relevant references such as:



\- industrial dashboard

\- enterprise data density

\- sidebar navigation

\- table patterns

\- dark/light visual systems

\- subtle motion

\- industrial visual language



It must NOT load the entire reference library.



\---



14\. Progressive Context Loading



Never send all skills, prompts, references, videos, and knowledge to the AI model.



Use:



Request

→ classify

→ select skills

→ select modules

→ semantic search

→ retrieve relevant references

→ generate design context

→ AI implementation



Only relevant context should be loaded.

15\. Source Preservation



For every source maintain:



\- source ID

\- motion language

\---



16\. Copyright / Safety



Do not automatically scrape, redistribute, or copy copyrighted website assets.



Local user-provided reference assets may be analyzed and indexed.



External resources should primarily be used for:



\- knowledge

\- principles

\- APIs

\- documented libraries

\- inspiration



Do not reproduce proprietary designs verbatim.



\---



17\. Final Goal



The result must be a portable, reusable UI/UX intelligence system that can be attached to a new project and produce a project-specific design system.



It should improve:



\- UX

\- UI

\- visual quality

\- frontend implementation

\- responsive behavior

\- accessibility

\- motion

\- 3D

\- interaction

\- design consistency



without forcing every project to look the same.
